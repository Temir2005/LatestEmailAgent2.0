Тематические дела

Переписка, разложенная по смыслу. Одно дело может собирать несколько технических цепочек — и наоборот, одна цепочка может распасться на два дела.

—

Агент не смог разобраться сам

Когда письмо непонятно контекстно, агент не угадывает, а спрашивает. Ответ становится фактом и подмешивается во все дальнейшие разборы — один и тот же вопрос второй раз не задаётся.

Технические цепочки

Уровень без ИИ: письма связаны по Message-ID, In-Reply-To и References (RFC 5322). Где заголовков не хватило, цепочка собрана эвристикой — тема, участники, окно по времени — и помечена честно.

—

Чат по всей переписке

Здесь можно спрашивать о переписке, искать письма, добавлять их в дела и готовить письма к отправке.

Источники писем

Демо-корпус — готовая тест-фикстура с намеренно поломанным threading. IMAP — ваш реальный ящик, доступ только на чтение.

Демо-корпус

10 писем от трёх организаций: корректная цепочка с References, счёт от noreply без заголовков, разорванная посередине цепочка, письмо с двумя разными вопросами и письмо без контекста вовсе. На нём видно всё поведение агента сразу.

Живой ящик по IMAP

Читает почту по учётным данным из .env. Письма не удаляются и не помечаются прочитанными. Массовые рассылки отсеиваются по заголовкам List-Unsubscribe и Precedence ещё до разбора.

Куда уходят тексты

Разбор идёт через API выбранного провайдера — тексты писем покидают машину. На этапе отбора медицинской переписки отправляются только отправитель, тема и даты; тела писем уходят лишь для отобранных цепочек. У Gemini выставлен store: false, поэтому интеракции на их стороне не сохраняются. Отправка из чата выполняется через SMTP только после отдельного подтверждения.
